# BUG-106 — Una colección filtrada vacía responde 404

Autor (portafolio): Diego Silva — diegosilva.itsu@gmail.com
Reportado por: equipo de soporte
Severidad: media
Estado: abierto

## Síntoma

Cuando un filtro de colección válido no tiene coincidencias, `GET /requests`
responde `404`.

Pasos para reproducirlo (con el seed del taller):

1. Iniciar sesión como `ana.requester.seed@example.test`.
2. Pedir `GET /requests?status=closed` con su token.
3. Observar la respuesta.

Ana no tiene solicitudes cerradas, así que el filtro es válido y no coincide con
nada.

## Comportamiento esperado

Una colección válida sin coincidencias debe responder:

```http
200 OK
```

```json
[]
```

Una colección vacía no es un recurso faltante. El `404` es para un recurso
individual que no existe (o que no debe revelarse); ver el contrato de la Clase
03 para colecciones.

## Definición de terminado

1. `GET /requests?status=closed` (como Ana) responde `200` con `[]`.
2. El resto de la suite sigue pasando.
3. Una prueba de regresión fija el comportamiento para que no vuelva en silencio.
